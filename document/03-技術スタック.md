## 3.2 技術選定理由

### なぜ Vite + React?

**Vite を選んだ理由:**
```
✓ Three.jsとの相性が最高
✓ HMRが爆速（アニメーション調整に最適）
✓ シンプルな設定
✓ 軽量で高速なビルド
✓ 多くのThree.jsサンプルがVite使用
```

**Next.jsではなくViteを選んだ理由:**
- SSR/SSG不要（SPA構成）
- アニメーション開発でリロード頻度が高い
- バックエンド分離のメリット
- 詳細は [[01-プロジェクト概要|プロジェクト概要]]参照

### なぜ Three.js + VRM?

**Three.js:**
```
✓ 業界標準のWebGL ライブラリ
✓ 豊富なドキュメント・コミュニティ
✓ パフォーマンスが優秀
✓ 拡張性が高い
```

**VRM:**
```
✓ アニメ調3Dアバターの統一規格
✓ 日本発の規格で日本語リソース豊富
✓ BlendShape（表情）サポート
✓ アニメーション互換性が高い
```

関連: [[04-アバター表示機能|アバター表示機能]]

### なぜ FastAPI?

```
✓ Python AIライブラリとの親和性
✓ 非同期処理のサポート
✓ 自動APIドキュメント生成
✓ 型ヒントによる堅牢性
✓ 高速（Starlette + Pydantic）
```

関連: [[10-API仕様|API仕様]]

### なぜ FastAPI + Mangum?

**FastAPI:**
```
✓ Python AIライブラリとの親和性
✓ 非同期処理のサポート
✓ 自動APIドキュメント生成
✓ 型ヒントによる堅牢性
✓ 高速（Starlette + Pydantic）
```

**Mangum:**
```
✓ FastAPIをLambdaで実行可能に
✓ API Gatewayとシームレス統合
✓ ローカル開発とLambda環境の統一
✓ 追加設定ほぼ不要
```

関連: [[16-SAM移行計画|SAM移行計画]]

### なぜ AWS SAM?

**サーバーレスのメリット:**
```
✓ コスト削減（使った分だけ課金）
✓ 自動スケーリング
✓ 運用負荷の削減
✓ コールドスタート対策可能
```

**SAMのメリット:**
```
✓ CloudFormationより簡潔
✓ ローカルテスト環境統合
✓ デプロイが簡単（sam deploy）
✓ AWS公式ツール
```

**Terraformではない理由:**
```
✗ サーバーレスに最適化されていない
✗ ローカル開発環境の統合が弱い
✗ Lambda関数管理が煩雑
✓ SAMはサーバーレス特化で効率的
```

関連: [[16-SAM移行計画|SAM移行計画]]

### なぜ AWS Bedrock (Nova)?

**AWS Bedrock:**
```
✓ AWS ネイティブ統合 (IAM認証)
✓ Lambda から低レイテンシでアクセス
✓ リージョン内通信でコスト削減
✓ スケーラブルな従量課金
```

**Nova Model:**
```
✓ 高品質な日本語対話生成
✓ 感情分析・文脈理解に対応
✓ コストパフォーマンスが優秀
✓ AWS 最新の基盤モデル
```

**OpenAIではない理由:**
```
✗ 外部API呼び出しでレイテンシ増加
✗ APIキー管理が必要
✗ AWS統合が弱い
✓ Bedrockは AWS エコシステムに最適
```

関連: [[06-AI対話機能|AI対話機能]]

### なぜ Amazon Polly?

**Amazon Polly (Neural TTS):**
```
✓ AWS ネイティブ統合
✓ 自然な日本語音声 (Neural TTS)
✓ Lambda から直接呼び出し可能
✓ リアルタイム音声合成対応
✓ SSML サポートで感情表現可能
```

**Google Cloud TTSではない理由:**
```
✗ 外部サービス認証が必要
✗ クロスクラウド通信でレイテンシ
✗ コスト最適化が困難
✓ Pollyは AWS エコシステムに最適
```

関連: [[05-アニメーション機能#リップシンク|リップシンク]]

## 3.4 開発環境セットアップ

### フロントエンド

```bash
# プロジェクト作成
npm create vite@latest ai-avatar-frontend -- --template react-ts

# 依存関係インストール
cd ai-avatar-frontend
npm install three @pixiv/three-vrm gsap zustand axios

# 開発サーバー起動
npm run dev
# → http://localhost:5173
```

### バックエンド

```bash
# 仮想環境作成
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

# 依存関係インストール
pip install -r requirements.txt

# ローカル開発サーバー起動（推奨）
python local_server.py
# → http://localhost:8000
# → http://localhost:8000/docs (Swagger UI)

# または SAM CLI でLambda環境テスト
cd ../infrastructure
sam local start-api
# → http://localhost:3000
```

## 3.5 AWS サービス設定

### AWS Bedrock

```bash
# .env (ローカル開発用)
AWS_REGION=ap-northeast-1
AWS_PROFILE=default

# Bedrock設定
BEDROCK_MODEL_ID=amazon.nova-micro-v1:0  # または nova-lite, nova-pro
BEDROCK_REGION=us-east-1  # Bedrock利用可能リージョン
```

設定方法:
1. AWS コンソールで Bedrock モデルアクセスを有効化
2. Nova モデルのアクセス申請 (即時承認)
3. Lambda 実行ロールに Bedrock 権限付与

### Amazon Polly

```bash
# .env (ローカル開発用)
POLLY_VOICE_ID=Takumi  # 日本語男性音声
# または Mizuki (女性), Kazuha (女性 - Neural)

POLLY_ENGINE=neural  # standard または neural
```

設定方法:
1. Lambda 実行ロールに Polly 権限付与
2. 音声サンプルでテスト (AWS Console)
